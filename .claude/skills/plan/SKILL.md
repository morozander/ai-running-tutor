# /plan — Implementation Planning

Called by `/work` when state phase is `planning`. Produces a structured markdown plan that the dev reviews before any code is written. **The cheapest expensive thing to get right.**

## Model strategy

Three subagents, tiered:

| Step | Subagent | Model | Why |
|---|---|---|---|
| 1. Explore codebase | `explorer` | haiku | Read + summarize |
| 2. Draft plan | `planner` | sonnet | Architectural reasoning at acceptable cost |
| 3. Quality gate | `plan-reviewer` | opus | One pass of deep review on a small input — high impact, low spend |

The driver `/work` itself stays on the user's default (typically Sonnet). Opus is invoked ONLY for `plan-reviewer`.

## Inputs

- Active state at `.claude/state/<TICKET>.json`
- Raw ticket at `.agentic/plans/<TICKET>/raw.json`
- Optional overrides at `.agentic/plans/<TICKET>/overrides.md`
- Figma frame data at `.agentic/plans/<TICKET>/figma/*.json` (if available)
- **Canary token** for this pass — `CANARY-<random-word>-<4 digits>`, generated by the `/work` driver and passed in (see "Canary + evidence protocol")

## Canary + evidence protocol (per pass)

The `/work` driver generates ONE canary token per pass — `CANARY-<random-word>-<4 digits>` — and
passes it to this skill. Inject it **verbatim** into EVERY subagent dispatch (explorer, planner,
plan-reviewer). Each subagent MUST echo the canary verbatim in its return — a missing/altered
canary means the return is suspect → **re-dispatch**.

Each subagent returns a machine-checkable `evidence` block. `/plan` is a read-only phase, so there
are no commit SHAs; the block carries the artifact path(s) it wrote (`exploration.md` / `plan.md`
/ `plan-review.md`), exact counts copied from its own output (e.g. tasks in the plan, affected
packages, review findings), and — for the code-navigating explorer/planner —
`lsp: { calls, usedFor }` (validated per the LSP enforcement rule). Numbers must be COPIED from
real output, never estimated.

**RE-CHECK the evidence (the teeth).** Confirm each claimed artifact path exists; cross-check a
reported count against the file itself (e.g. count the tasks in `plan.md` vs the planner's claim);
confirm the canary echo. A claimed artifact that isn't there, or a count that contradicts the file
→ a `hallucination_flag` → re-dispatch or ESCALATE, never trusted.

## Procedure

### 1. Dispatch explorer (haiku)

```
Task(
  subagent_type: "explorer",
  prompt: "Explore for relevant code for ticket <TICKET>. User story: ...
           ACs: ...
           Search breadth: medium.
           Foundation requirements: check against .agentic/rules/_shared/foundation-prerequisites.md

           CANARY: echo verbatim in your return — <CANARY>.
           EVIDENCE: return an `evidence` block — the exploration.md path written, exact counts
           copied from real output, and `lsp: { calls, usedFor }`. Numbers copied, never estimated."
)
```

Explorer writes `.agentic/plans/<TICKET>/exploration.md`.

### 2. Dispatch planner (sonnet)

```
Task(
  subagent_type: "planner",
  prompt: "Produce .agentic/plans/<TICKET>/plan.md from:
           - Raw ticket at .agentic/plans/<TICKET>/raw.json
           - Exploration at .agentic/plans/<TICKET>/exploration.md
           - Overrides at .agentic/plans/<TICKET>/overrides.md (if exists)
           - Cached Figma frame JSONs at .agentic/plans/<TICKET>/figma/*.json (if any) —
             read these for UI structure/layout; they are the source for screen/route targets
           - Foundation decision from state: <foundation_decision>
           - Ticket type from state: <ticket_type> — shapes task structure
             (bug → failing-repro-test task first; refactor → invariant-preservation
             acceptance; see constraint 17 in planner.md)
           
           Follow the constraints in .claude/agents/planner.md.
           Classify each task: code | foundation | migration | environment | iaac.
           Foundation tasks come first in the DAG.
           Environment tasks go in plan but NOT implemented by /implement —
           they flow into /handoff's Deployment Prerequisites section.
           Populate an 'Affected Packages' list for the plan, and for each UI task name
           the target screen(s)/route(s). These are consumed downstream by build-check,
           runtime-smoke, and design-parity — do not leave them blank on UI work.

           CANARY: echo verbatim in your return — <CANARY>.
           EVIDENCE: return an `evidence` block — the plan.md path written, exact counts copied
           from real output (tasks, affected packages), and `lsp: { calls, usedFor }`. Numbers
           copied, never estimated."
)
```

Planner writes `.agentic/plans/<TICKET>/plan.md`.

### 3. Dispatch plan-reviewer (opus)

```
Task(
  subagent_type: "plan-reviewer",
  prompt: "Review the planner draft at .agentic/plans/<TICKET>/plan.md against the
           checks in .claude/agents/plan-reviewer.md. Return either APPROVED (append
           a Plan Review section to plan.md) or NEEDS_REWORK (write feedback to
           .agentic/plans/<TICKET>/plan-review.md).

           CANARY: echo verbatim in your return — <CANARY>.
           EVIDENCE: return an `evidence` block — the verdict, the artifact path written
           (plan.md section or plan-review.md), and the review-findings count copied from real
           output. Numbers copied, never estimated."
)
```

### 4. Handle plan-reviewer feedback

Before acting on any subagent return, re-check its evidence per "Canary + evidence protocol"
(canary echoed verbatim, claimed artifact exists, reported counts match the file). A missing
canary → re-dispatch; a count that contradicts the file → `hallucination_flag`.

- **APPROVED** — continue to step 5
- **NEEDS_REWORK** — re-invoke planner with the feedback as input. Cap: 2 reviewer cycles. If still failing after 2, surface to dev: "Plan keeps failing review. See `.agentic/plans/<TICKET>/plan-review.md` for issues; could you clarify the ticket?"

### 5. Save plan version (if regenerating)

If a previous `plan.md` exists from a prior call, rename to `plan.v1.md`, `plan.v2.md`, etc. before overwriting.

### 6. Update state + return

```bash
node .claude/scripts/state-update.mjs "$state_file" set phase=plan-review
node .claude/scripts/state-update.mjs "$state_file" append-history --summary "<plan summary>"
#   ↳ ts + duration_s are stamped automatically (locked write path — work/SKILL.md §4)
```

Return to driver. Driver presents the plan with the conversational pause prompt (see `/work` SKILL.md).

On return, `/plan` surfaces its OWN `evidence` block to the driver: the artifact paths written
(`exploration.md`, `plan.md`, any `plan-review.md`), the task / affected-package counts read back
from `plan.md` itself, and the reviewer verdict — every number COPIED from the files, never
estimated. The driver re-checks this sample in turn.

## Re-generation flow

When the dev requests plan changes (after the pause):

```
Dev: "regenerate task t3 to use Apollo cache.evict instead of refetchQueries"
```

The driver invokes `/plan` again with the dev's constraint as an additional input. The planner reads the previous `plan.md`, applies the change, the plan-reviewer re-validates, and the cycle repeats.

## Two-phase plan (optional, for cross-cutting work)

If the ticket touches > 3 packages OR > 8 tasks OR planner reports `high` complexity:

1. **High-level plan first** — task titles + dependencies + affected packages only
2. Dev approves the high-level shape
3. **Detailed expansion** — full task spec

Triggered automatically by the planner when these thresholds hit. Otherwise single-pass.

## Hard rules

- ❌ Never present the plan to the dev without plan-reviewer's approval
- ❌ Never overwrite a previous plan version (rename to `.vN.md` first)
- ❌ Auto-approving the plan — always pause for dev sign-off after plan-reviewer approves
- ❌ Modifying any code from within /plan — read-only phase
- ❌ Skipping the explorer pass even on simple tickets — references come from the codebase, not from the model's memory
- ❌ Trusting a subagent return whose canary is missing/altered — re-dispatch
- ❌ Presenting a plan without re-checking the planner's evidence — the artifact must exist and its counts must match `plan.md`; a contradiction is a `hallucination_flag`
