# Monorepo AGENTS.md

Root context for AI coding agents (Claude Code, Cursor, Codex, etc.). Both `AGENTS.md` and `CLAUDE.md` (a symlink) point here.

## Repository overview

This monorepo contains a complete product stack:

| Package | Stack | Deploys to |
|---|---|---|
| [backend/](../backend) | NestJS 11 + TypeScript + GraphQL + MikroORM + Postgres | AWS Lambda (via ECR) |
| [frontend/](../frontend) | React 19 + Vite 7 + Apollo 4 + Tailwind 4 + RHF/Zod | S3 + CloudFront |
| [mobile/](../mobile) | Expo SDK 54 + Expo Router + Apollo 4 + AWS Amplify | iOS / Android stores |
| [iaac/](../iaac) | Terragrunt + Terraform + AWS (VPC, RDS, Cognito, Lambda, S3, CloudFront, Bedrock, SQS/SNS) | AWS |

CI/CD: GitLab CI (`.gitlab/ci/`). GitHub migration is in progress — some projects use `.github/workflows/`. The handoff skill detects the remote at runtime.

## How rules are organized

This repo uses a **tool-agnostic rules system** under `.agentic/`. Source of truth lives there; tool-specific files (Cursor `.mdc`, Claude `CLAUDE.md` symlinks) are generated by [scripts/sync.ts](./scripts/sync.ts).

```
.agentic/
├── AGENTS.md                # this file
├── rules/
│   ├── _shared/             # cross-stack rules (kebab-case, typescript, commits, branches)
│   ├── backend/             # NestJS architecture, MikroORM, GraphQL, auth, Lambda, OTel
│   ├── frontend/            # React architecture, Apollo, Tailwind, RHF/Zod, routing, UX
│   ├── mobile/              # Expo Router, RN components, native modules, platform files
│   └── iaac/                # Terragrunt, AWS conventions, secrets
├── guides/                  # human-facing input contracts (BA ticket authoring, designer handoff)
├── packages/                # per-package AGENTS.md (loaded as ambient context)
└── scripts/
    └── sync.ts              # regenerates .cursor/rules + CLAUDE.md symlinks
```

## Rule loading

- **Cursor**: reads `.cursor/rules/*.mdc` — generated from `.agentic/rules/**/*.md`
- **Claude Code**: reads root `CLAUDE.md` (symlinked to this file) + per-package `<pkg>/CLAUDE.md` symlinks
- Per-package context: when working in `backend/`, the agent should also load `.agentic/packages/backend.md`

## Architectural principles

1. **Vertical-slice backend** — domain modules are read-only, feature modules own mutations. Strict layering.
2. **Code-first GraphQL** — `@ObjectType()` + `@Entity()` on the same class.
3. **Codegen everywhere** — backend GraphQL types feed FE/mobile codegen. Never hand-write API types.
4. **Independent app workspaces** — backend, frontend, mobile each have their own `package.json`. Not a pnpm/Nx workspace.
5. **Tool-agnostic where reasonable** — `.agentic/` source generates `.cursor/` and Claude artifacts.

## Conventions referenced often

- File naming: kebab-case ([rules/_shared/kebab-case.md](./rules/_shared/kebab-case.md))
- TypeScript: prefer `type` over `interface`, no `any` ([rules/_shared/typescript.md](./rules/_shared/typescript.md))

## Running the sync script

After editing files under `.agentic/rules/` or `.agentic/packages/`:

```bash
cd .agentic/scripts
pnpm install   # first time only
pnpm sync      # regenerates .cursor/rules and CLAUDE.md symlinks
```

Commit the regenerated outputs alongside the source changes — `.cursor/rules/` is tracked.

## How a dev launches the workflow

```bash
git clone <repo> && cd <repo>
mise install                     # pinned toolchain: node 22.22, pnpm 9.15, jq, direnv, typescript-language-server
mise run bootstrap               # corepack + per-app deps + setup-claude.sh (Jira PAT) + direnv allow
code . / cursor .                # IDE launched from a shell that has the env

# Claude Code (plugins are declared in .claude/settings.json — accept the prompts, or):
#   /plugin install superpowers@claude-plugins-official
#   /plugin install typescript-lsp@claude-plugins-official       # LSP code-intelligence (less context-search)
#   /plugin install security-guidance@claude-plugins-official    # in-session security review
#   /reload-plugins
#   /mcp                         # internal-jira + figma (pre-enabled in settings.json)
#   /work PROJ-XYZ

# Cursor (skills/agents/rules/hooks load automatically — see .cursor/README.md):
#   superpowers: enabled via committed .cursor/settings.json — if its skills are
#   missing on a fresh machine, run /add-plugin superpowers once (session-start nudges)
#   figma OAuth pops on first MCP use; typescript-lsp/security-guidance/playwright
#   have native equivalents in Cursor and are deliberately not installed
#   /work PROJ-XYZ
```

See [.claude/ONBOARDING.md](../.claude/ONBOARDING.md) for the full walkthrough and troubleshooting (both harnesses).

## House tone (easter eggs — optional; a team that wants it strictly neutral can delete this section)

These shape ONLY the conversational + status text the assistant shows the developer in chat. They must **NEVER** appear in anything committed or outward-facing — code, comments, commit messages, branch names, PR/MR descriptions, Jira comments, design notes, or verifier report JSON all stay strictly professional. Flavor never delays, softens, or obscures a real finding, a status, or a refusal to pass blind.

- Address the developer as **"bro"** in chat — collegial and warm, sprinkled naturally, not jammed into every sentence.
- When a ticket reaches `review-ready` on the **first verify pass with zero fix loops**, you've earned one short celebratory line (e.g. *"🎯 first-try green, bro"*). Once per ticket — not confetti on every phase.
- When the developer clears a human-blocker the run was parked on (Docker up, creds supplied, SSO re-login), a quick *"back in business 🚀"* as you resume is welcome.
- On the rare day the whole pipeline is green AND IaC was provably untouched, a quiet *"clean run, nothing on fire"* is allowed. Earn it; don't fake it — a green you can't back is worse than an honest escalation.
