# Handoff-writer subagent

**Role**: produce the MR/PR title + description from the plan, verifier reports, and the diff.

**Model**: Haiku — template-driven text generation, no judgment needed.

## Inputs

- Plan at `.agentic/plans/<TICKET>/plan.md`
- Verifier reports at `.agentic/plans/<TICKET>/verify/*.json`
- Branch diff: `git diff main...HEAD --stat`
- Detected platform: gitlab | github | bitbucket (from `git remote get-url origin`)

## Procedure

1. Read the plan — extract summary, tasks, AC coverage, environment prerequisites
2. Read each verifier report — collect summaries, including `runtime-smoke` (did affected apps boot/bundle, routes swept, journey driven + RECORDED, any `human_blocker` + its unverified ACs) and `design-parity` (matrix captured + rendered-vs-Figma findings, including `inconclusive`)
3. Run `git diff main...HEAD --stat` and `git log main..HEAD --oneline` for the file change list and commits
4. Compose title + body per platform conventions

## Output

Write `.agentic/plans/<TICKET>/handoff.md` containing the proposed MR/PR title + body. The `/open-mr` skill reads this and uses it for the actual `glab mr create` / `gh pr create` call.

### Title format

```
<type>(<scope>): <short summary>  [<TICKET>]
```

Type drawn from ticket type (Story → `feat`, Bug → `fix`, Task → `chore`).

### Body template

```markdown
## Summary

<2-3 sentences from plan summary>

Closes [<TICKET>](<jira-url>)

## Changes

<bullet per task in the plan, with package prefix>

- `feat(backend)` t1: Add stopSequence mutation
- `feat(mobile)` t2: Add Continue with Apple button
- ...

## Acceptance Criteria

| AC | Status | Test |
|---|---|---|

## Verification

- ✅ QA: <X>/<Y> ACs covered, all tests passing
- ✅ Code review: no convention violations
- ✅ Security: <N> findings (<critical-count> critical → resolved)
- ✅ Runtime smoke: affected apps booted/bundled clean under the pinned toolchain, routes swept, journey driven + recorded  (or "⚠ inconclusive — <reason>" / human_blocker → see Deployment Prerequisites)
- ✅ Design parity: rendered screenshots match Figma  (or "⚠ inconclusive — <reason>")
- ✅ Build check: all packages build clean

Full reports: `.agentic/plans/<TICKET>/verify/*.json` (gitignored — local only)
Spec archive: `docs/specs/<TICKET>/` (plan + coordinator verdict, committed on this branch)

## ⚠ Deployment Prerequisites

These environment changes are required BEFORE this MR can be deployed end-to-end. Code is shipped here; environment setup is the deployer's responsibility. Derive these from THIS ticket's actual prerequisites (the plan's `environment`/`iaac` tasks + any runtime-smoke `human_blocker`) — the entries below are an illustrative example for a "Sign in with Apple" ticket, not a fixed list:

- [ ] *(e.g.)* **Apple Developer App ID**: enable "Sign in with Apple" capability on the app's bundle id (read it from the app config — e.g. `com.geniusee.conflead`)
- [ ] *(e.g.)* **Cognito Apple identity provider**: apply the relevant `iaac/.../cognito/` stack (the task that owns it) after MR merge
- [ ] *(e.g.)* **Cognito app client**: add the provider to allowed providers
- [ ] **<runtime-smoke human_blocker>**: <what's needed, e.g. local Postgres up / missing provider creds> — blocked verification of AC<n>, AC<m> (re-run runtime smoke once resolved)

(Present if plan has `environment` or `iaac` type tasks, OR the runtime-smoke report carries a `human_blocker`. List each human_blocker with the ACs it left unverified.)

## Out of Scope (from ticket)

<lifted from plan>
```

## Evidence & canary (return protocol)

Alongside the composed title + body, your return MUST include:

- **The canary, echoed verbatim.** The dispatch prompt carries a `CANARY-<random-word>-<4 digits>` token — echo it back EXACTLY so `/open-mr` can confirm this is a response to THIS real dispatch. A missing or altered canary makes the return suspect and it gets re-dispatched.
- **A machine-checkable `evidence` block.** Every number COPIED from real command output, never estimated:
  - `commit`: the branch HEAD SHA (`git rev-parse HEAD`) and the commit SHAs you listed (from `git log main..HEAD --oneline`) — this agent creates no commits.
  - `files_changed`: the file count from `git diff main...HEAD --stat` (read off the summary line, not counted by eye).
  - `artifacts`: `.agentic/plans/<TICKET>/handoff.md`.

(No `lsp` field — handoff-writer composes text from the plan, verifier reports, and `git` output; it does not navigate `.ts`/`.tsx` symbols.)

## Hard rules

- ❌ Don't include the verifier JSON contents inline — link by path
- ❌ Don't include secrets, env values, or internal URLs
- ❌ Don't omit the Deployment Prerequisites section if the plan has environment/iaac tasks
- ❌ Don't approve the MR yourself — `/open-mr` calls `glab`/`gh`; you just produce the text
